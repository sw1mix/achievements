# Достижения

Минималистичный трекер привычек: сетка «достижение × день» за неделю или месяц, статистика периода, ритм за последние 12 недель и тепловая карта года.

Без сборки и зависимостей — четыре файла (`index.html`, `styles.css`, `core.js`, `app.js`), данные хранятся в `localStorage` браузера.

## Возможности

- Два периода: неделя (Пн–Вс) и месяц; текущий день подсвечен, выходные приглушены
- Навигация стрелками на экране или клавишами ←/→, кнопка «Сегодня»
- Добавление и переименование достижений (клик по названию)
- **Значок** — смайлик или короткий текст (до 3 символов). Смайлик подбирается
  автоматически по названию: «Тренировка» → 🏃, «Чтение» → 📚, «2 литра воды» → 💧.
  Значок, цвет и цель настраиваются и при создании, и позже — кликом по значку
- **Цель по частоте** — от 1 до 7 раз в неделю. В режиме месяца цель пересчитывается
  пропорционально (3 раза в неделю ≈ 13 раз в месяц). Прогресс считается относительно
  цели: перевыполнение показывается отдельно и не раздувает общий процент
- **Порядок строк** меняется перетаскиванием за ручку слева либо стрелками ↑/↓,
  когда ручка в фокусе
- **Архив вместо удаления**: достижение убирается из сетки и статистики, но история
  отметок сохраняется. Из архива можно вернуть или удалить безвозвратно
- Круговые диаграммы: общий прогресс к целям за период + по каждому достижению
- Сводка: процент периода, число закрытых целей, лучший день, текущая серия
- Ритм: распределение по дням недели и итоги по неделям за 12 недель с засечкой цели
- Год: тепловая карта по дням с навигацией по годам
- Светлая и тёмная тема, выбранный период и год запоминаются
- Экспорт/импорт данных в JSON
- Изменения в одной вкладке подхватываются другими открытыми вкладками
- **Устанавливается на телефон и работает офлайн** (см. ниже)

### Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| ←/→ | предыдущий/следующий период |
| T | вернуться к сегодняшнему дню |
| W / M | режим недели / месяца |
| ↑/↓ | переместить достижение (когда ручка слева в фокусе) |
| Esc | закрыть настройку достижения |

## Структура

| Файл | Назначение |
| --- | --- |
| `core.js` | чистая логика: даты, агрегация статистики, миграция и валидация данных |
| `app.js` | рендер интерфейса и обработка ввода |
| `index.html`, `styles.css` | разметка и оформление |
| `sw.js`, `manifest.webmanifest`, `icons/` | офлайн-режим и установка на устройство |
| `tests/core.test.js` | тесты логики на `node:test` |

Логика намеренно отделена от DOM: `core.js` не обращается к документу и подключается
как в браузере (`window.AchievementsCore`), так и в тестах через `require`.

## Локальный запуск

Достаточно открыть `index.html` в браузере. Либо поднять локальный сервер:

```bash
python3 -m http.server 8000
```

## На телефоне

Приложение открывается по адресу сайта в обычном браузере, но его стоит установить
на домашний экран:

- **Android (Chrome):** кнопка «Установить» в шапке либо меню браузера → «Установить приложение»
- **iOS (Safari):** «Поделиться» → «На экран Домой»

Установка даёт три вещи: запуск с иконки без адресной строки, работу без интернета
и — самое важное — сохранность данных. Safari на iOS очищает `localStorage` сайта,
если им не пользовались около недели; у приложения, добавленного на домашний экран,
данные так не удаляются.

Офлайн обеспечивает `sw.js`: файлы отдаются из кэша и параллельно обновляются из сети,
поэтому новая версия подхватывается со следующего запуска без ручного сброса кэша.
Service worker требует HTTPS или localhost — при открытии `index.html` двойным щелчком
он просто не регистрируется, всё остальное работает.

Интерфейс рассчитан на касания: отметка ставится нажатием в любом месте ячейки, а не
только по самому квадратику; колонка с названиями закреплена при горизонтальной прокрутке.

## Тесты

```bash
npm test          # или: node --test tests/
```

Требуется Node.js 18+ (используется встроенный тест-раннер, зависимостей нет).

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и запушьте содержимое этой папки:

```bash
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Workflow `.github/workflows/deploy.yml` прогоняет тесты и публикует сайт при каждом пуше в `main`;
`ci.yml` прогоняет тесты в merge/pull request. Адрес будет `https://<логин>.github.io/<репозиторий>/`.

## Данные

Всё хранится локально в браузере под ключом `achievements.v1`, на сервер ничего не уходит.
Чтобы перенести историю на другое устройство, используйте «Экспорт» и «Импорт».

Текущая версия схемы — 3. При загрузке данные проходят через миграцию: файлы прежних
версий дочитываются без потерь (значок из версии 2 сохраняется, отсутствующий подбирается
по названию, цель выставляется в «каждый день»), а повреждённые записи — неизвестные
привычки, некорректные даты, дубликаты `id` — отбрасываются.

```jsonc
{
  "version": 3,
  "habits": [
    {
      "id": "a1b2c3d4",
      "name": "Тренировка",
      "color": "#2f6fed",
      "badge": { "type": "emoji", "value": "🏃" }, // либо { "type": "text", "value": "Тр" }
      "goal": 3,                                   // раз в неделю, 1..7
      "createdAt": "2026-01-01",
      "archivedAt": null                           // дата — если достижение в архиве
    }
  ],
  "done": { "2026-09-17": { "a1b2c3d4": true } }
}
```
